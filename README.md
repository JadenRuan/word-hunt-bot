# Word Hunt Bot

Fully-automated player for GamePigeon's **Word Hunt**, driven by macOS's **iPhone Mirroring** app.

The bot:
1. Captures the mirrored iPhone screen
2. OCRs the 4×4 letter grid
3. Finds every valid word with a trie-backed DFS
4. Plays them by simulating mouse swipes — iPhone Mirroring forwards those as touch swipes to your phone

---

## Requirements

- macOS 15 (Sequoia) or later — for the **iPhone Mirroring** app
- Python 3.10+
- Tesseract OCR

## Setup

```bash
cd ~/.../word_hunt_cheat

# 1. Install Tesseract
brew install tesseract

# 2. Python deps
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 3. Word list (~370k English words)
curl -L -o words.txt https://raw.githubusercontent.com/dwyl/english-words/master/words_alpha.txt
```

### macOS permissions

The bot needs two permissions for the Terminal (or VS Code, whichever you run from):

1. **System Settings → Privacy & Security → Screen Recording** — to read the iPhone Mirroring window
2. **System Settings → Privacy & Security → Accessibility** — to send mouse events

Restart the terminal after granting these.

## Usage

```bash
# 1. Open iPhone Mirroring, launch GamePigeon → Word Hunt, get to the round-start screen.

# 2. One-time calibration: tells the bot where the 4x4 grid is on your screen.
python calibrate.py

# 3. Start the bot. It listens for a hotkey.
python main.py
```

Then in Word Hunt: tap **Start** to begin a round, and immediately press **⌘⇧W**. The bot reads the board, computes every word, and starts swiping highest-value words first.

If you move the iPhone Mirroring window, re-run `calibrate.py`.

## Files

| File | Purpose |
|---|---|
| `solver.py` | Trie + DFS word finder, Word Hunt scoring |
| `vision.py` | Screen capture + per-cell OCR (multi-variant + majority vote) |
| `automation.py` | Mouse swipe gestures |
| `calibrate.py` | One-time grid corner calibration |
| `main.py` | Hotkey listener, orchestration, manual-fill fallback |
| `debug_capture.py` | OCR diagnostic — dumps raw + preprocessed cells |
| `test_swipe.py` | Input diagnostic — sends one test swipe |
| `calibration.json` | Generated by `calibrate.py` |
| `words.txt` | Dictionary (downloaded above) |

## Tuning

### Swipes not registering

If `main.py` says it's swiping but the iPhone shows nothing, work through these in order:

**1. Sanity-check with the test script.**

```bash
python test_swipe.py
```

It activates iPhone Mirroring, waits 1.5 s, then drags diagonally across the grid. If you don't see a finger trail, input isn't reaching the iPhone at all and you stop here until that's fixed.

**2. Accessibility permission.** The single most common cause. macOS *silently drops* synthetic mouse events from any app that doesn't have Accessibility access. The bot warns you at startup, but to verify by hand:

- System Settings → Privacy & Security → **Accessibility**
- Find the app you launched the bot from (Terminal, iTerm, VS Code, etc.) — add it if it's not there, and make sure the toggle is **on**
- **Quit and relaunch that app** — toggling alone isn't enough, the process needs to restart to pick up the new permission

**3. iPhone Mirroring not frontmost.** Mouse events at HID level go to whatever window is at those screen coords on top. If another window is covering iPhone Mirroring, the events miss. The bot calls `osascript` to activate iPhone Mirroring before each round, but if you renamed/localized the app you may need to adjust the AppleScript in `automation.focus_iphone_mirroring`.

**4. Timing.** If the test swipe shows a stuttering or partial trail, slow things down by editing `automation.py`:

- `STEP_DELAY` — pause between intermediate moves (try 0.020–0.030)
- `SEGMENT_STEPS` — interpolation steps per cell-to-cell hop (try 8–10)
- `DOWN_HOLD` — initial press hold before moving (try 0.10)

### OCR misreads

If `main.py` reports `?` cells, two tools to debug:

**1. Manual fill (built in).** When OCR fails, the bot prints the partial grid and prompts you to type each missing letter. Just look at your iPhone Mirroring window and type the letters. The round continues normally.

**2. Debug capture.** Get to the round-start screen, then in another terminal:

```bash
python debug_capture.py            # default padding 0.18
python debug_capture.py --padding 0.12   # if letters get cut off
python debug_capture.py --padding 0.24   # if borders bleed in
```

Open the generated `debug/` folder. For each cell you'll see:

- `cell_r{R}c{C}_*_raw.png` — what we cropped from the screen
- `cell_r{R}c{C}_*_v{N}=*.png` — each preprocessing variant + what Tesseract returned

If the **raw crop** looks bad (letter cut off or borders included), adjust `--padding`. If the raw is fine but **variants** look noisy, adjust thresholds in `vision._preprocess_variants`.

## Notes

- Word Hunt's actual dictionary is unknown, but `words_alpha.txt` from `dwyl/english-words` is a strong superset. Some submissions will be rejected as "not a word" — the bot just moves on to the next.
- The default time budget is 75 seconds (round is ~80). It plays words in score-descending order, so even if it doesn't finish the list, it gets the highest-value words first.
- **macOS failsafe**: pyautogui aborts if you fling the mouse to the top-left corner — emergency stop.
